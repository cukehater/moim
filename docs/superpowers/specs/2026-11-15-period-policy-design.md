# 투표 기간·상태 정책 정비 설계

## 의도
모임 상태(예정·진행 중·마감)가 편집 폼 저장, 조기 마감, 생성 같은 여러 경로에서 의도치 않게 바뀐다. 상태가 바뀌는 길을 버튼(조기 마감·투표 재개)으로 모으고, 재개 모달 버그를 고친 뒤 코드 전체의 구멍을 전수 검사해 고친다.

## 정책 (사용자 결정)
1. 상태는 버튼으로만 바뀜
   - 마감된 모임: 편집 폼에서 시작·종료 시각 변경 불가. 안내 "마감된 모임은 기간을 바꿀 수 없어요. 투표 재개를 이용해 주세요"
   - 진행 중·예정 모임: 종료 시각을 바꾸면 지금 이후여야 함
2. 시작된(진행 중) 모임은 시작 시각 변경 불가. 예정 모임만 가능
3. 예정 모임에는 조기 마감 없음 (버튼 숨김, 서버 거부)
4. 새 모임의 종료 시각은 지금 이후. 시작 시각은 과거 허용

서버(`upsertMeeting`, `closeMeeting`)가 최종 판단. 폼은 같은 규칙으로 잠금·오류 표시만.

## 접근 방식
- **순수 함수 하나에 규칙을 모음 (선택)**: `entities/meeting/model`에 기간 변경 검사 함수를 두고 서버 액션과 폼이 같이 씀. 단위 테스트로 규칙을 고정
- 서버 액션마다 조건문 직접 작성: 폼과 규칙이 갈라질 위험이 있어 제외

## 재개 모달 버그 (code-review 8건)
재개 실패(종료 지남)가 닫힌 모달 안에만 표시 → 모달을 열어 보여줌 / 닫으면 입력·오류 초기화, 입력 시 오류 지움 / 시작 이전 값에 맞는 문구 "시작 시각 이후로 입력해 주세요" / 입력 min=지금 / 조기 마감은 열린 모임에만 기록, 없는 모임은 실패 / [재개하기] pending 문구 / 높이 클래스 중복 정리

## 전수 검사
정책·버그 수정 후 새 검토자가 코드 전체 검사. 명백한 버그는 수정, 정책 판단이 필요한 건은 모아서 사용자에게 질문.

## 비목표
상태 저장 방식 변경(계속 계산), 시간대·DST 처리 변경
